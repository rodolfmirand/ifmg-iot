Apresentação
Esta apostila orienta a primeira etapa da disciplina Internet das Coisas III. O foco é a conectividade entre um dispositivo físico e serviços externos. O hardware será utilizado como plataforma experimental, mas não será objeto de ensino aprofundado nesta etapa.
Ao longo de 12 encontros, cada estudante desenvolverá individualmente a primeira parte de seu projeto: um ESP32 conectado por Wi-Fi, capaz de publicar dados de um sensor e receber comandos para um atuador por meio do protocolo MQTT. 1. Contextualização e objetivos
1.1 Situação-problema
Considere um ambiente que precisa ser monitorado remotamente. Um sensor produz leituras periódicas e um atuador deve ser acionado mesmo quando o usuário não está próximo do equipamento. O dispositivo físico não pode depender de uma conexão direta com o navegador do usuário. Ele precisa trocar mensagens com uma infraestrutura intermediária disponível na rede.
Nesta etapa, o ESP32 atua como dispositivo de borda. Ele se conecta a uma rede Wi-Fi e utiliza MQTT para publicar telemetria e receber comandos. O broker MQTT recebe, organiza e encaminha as mensagens. Nas etapas seguintes, um gateway em nuvem consumirá essas mensagens, persistirá dados e atenderá ao sistema web.
1.2 Objetivo geral
Implementar a conectividade de um dispositivo IoT baseado em ESP32, utilizando Wi-Fi e MQTT para comunicação bidirecional entre um sensor, um atuador e um broker acessível pela rede.
1.3 Objetivos específicos
* Representar a arquitetura inicial de uma solução IoT.
* Configurar o ESP32 para conectar-se a uma rede Wi-Fi.
* Diagnosticar endereço IP, intensidade do sinal e estado da conexão.
* Implementar reconexão automática ao Wi-Fi.
* Explicar o modelo publicação–assinatura do MQTT.
* Definir tópicos coerentes para telemetria, comandos e estado.
* Publicar mensagens estruturadas em JSON.
* Assinar tópicos e processar comandos recebidos.
* Acionar um atuador a partir de uma mensagem MQTT.
* Testar perda e recuperação de conectividade.
* Documentar decisões, testes e evidências do projeto individual.

6. Conectividade Wi-Fi
6.1 Revisão aplicada
O Wi-Fi fornece acesso à rede IP, mas não garante que o broker MQTT esteja disponível. É importante separar três estados: o dispositivo pode estar ligado, conectado ao ponto de acesso e, ainda assim, desconectado do serviço MQTT. O código deve observar essas camadas separadamente.
Indicador
	Pergunta de diagnóstico
	WiFi.status()
	O ESP32 está associado à rede?
	WiFi.localIP()
	Qual endereço IP foi atribuído?
	WiFi.gatewayIP()
	Qual gateway permite acesso a outras redes?
	WiFi.RSSI()
	Qual a intensidade aproximada do sinal?
	mqttClient.connected()
	A sessão com o broker está ativa?
	6.2 Exemplo completo de conexão
Conexão Wi-Fi com tentativas periódicas
#include <WiFi.h>
#include "secrets.h"

const unsigned long WIFI_RETRY_INTERVAL_MS = 5000;
unsigned long lastWifiAttempt = 0;

void printNetworkInformation() {
  Serial.print("IP local: ");
  Serial.println(WiFi.localIP());

  Serial.print("Gateway: ");
  Serial.println(WiFi.gatewayIP());

  Serial.print("Sinal (RSSI): ");
  Serial.print(WiFi.RSSI());
  Serial.println(" dBm");
}

void startWifiConnection() {
  Serial.print("Conectando à rede ");
  Serial.println(WIFI_SSID);
  WiFi.mode(WIFI_STA);
  WiFi.begin(WIFI_SSID, WIFI_PASSWORD);
  lastWifiAttempt = millis();
}

void maintainWifiConnection() {
  if (WiFi.status() == WL_CONNECTED) {
    return;
  }

  unsigned long now = millis();
  if (now - lastWifiAttempt >= WIFI_RETRY_INTERVAL_MS) {
    Serial.println("Wi-Fi desconectado. Nova tentativa...");
    WiFi.disconnect();
    WiFi.begin(WIFI_SSID, WIFI_PASSWORD);
    lastWifiAttempt = now;
  }
}

void setup() {
  Serial.begin(115200);
  startWifiConnection();
}

void loop() {
  maintainWifiConnection();

  static bool informationPrinted = false;
  if (WiFi.status() == WL_CONNECTED && !informationPrinted) {
    Serial.println("Wi-Fi conectado.");
    printNetworkInformation();
    informationPrinted = true;
  }

  if (WiFi.status() != WL_CONNECTED) {
    informationPrinted = false;
  }
}

Faixa aproximada
	Interpretação prática
	Acima de -50 dBm
	Sinal muito forte.
	-50 a -67 dBm
	Sinal geralmente adequado.
	-67 a -75 dBm
	Pode haver instabilidade dependendo do ambiente.

Observação
	RSSI é um indicador aproximado. Barreiras, interferência, lotação da rede e qualidade do ponto de acesso também influenciam a comunicação.
	

7. Fundamentos aplicados de MQTT
7.1 Modelo publicação–assinatura
MQTT é um protocolo leve de mensageria baseado em publicação e assinatura. Os clientes não precisam conhecer diretamente o endereço uns dos outros. Todos se conectam ao broker. Um cliente publica uma mensagem em um tópico, e o broker entrega essa mensagem aos clientes que assinam o mesmo tópico.
Fluxo MQTT bidirecional
ESP32 (publisher) ── publica ──► broker ── encaminha ──► gateway (subscriber)

Sistema web/gateway (publisher) ── publica comando ──► broker ── encaminha ──► ESP32 (subscriber)
	

7.2 Conceitos essenciais
Conceito
	Definição aplicada
	Broker
	Servidor responsável por receber e encaminhar mensagens.
	Cliente
	Aplicação ou dispositivo conectado ao broker.
	Tópico
	Nome hierárquico que identifica um fluxo de mensagens.
	Publicação
	Envio de uma mensagem a um tópico.
	Assinatura
	Registro de interesse em receber mensagens de um tópico.
	Payload
	Conteúdo da mensagem.
	Client ID
	Identificador da sessão do cliente.
	QoS
	Nível de garantia de entrega.
	Retained message
	Última mensagem que o broker pode guardar para novos assinantes.
	Last Will
	Mensagem preparada para indicar desconexão inesperada.

8. Mensagens JSON e convenções
8.1 Estrutura recomendada
Exemplo de telemetria
{
  "deviceId": "charles01",
  "sensor": "luminosidade",
  "value": 1875,
  "unit": "raw",
  "sequence": 42,

Nesta etapa, o timestamp oficial poderá ser acrescentado pelo gateway nas etapas seguintes. O ESP32 registra uptime e sequência para permitir análise básica de ordem e reinicialização, sem depender de relógio em tempo real.

Exemplo de comando
{
  "action": "set",
  "target": "led",
  "value": true,
  "requestId": "cmd-2026-001"
}
	8.3 Mensagem de estado confirmado
Exemplo de confirmação do atuador
{
  "deviceId": "charles01",
  "actuator": "led",
  "state": true,
  "requestId": "cmd-2026-001"
}
	

Por que confirmar o estado?
	A publicação do comando não prova que o atuador foi acionado. O dispositivo deve processar o comando e publicar o estado resultante. Essa confirmação será importante para o sistema web nas etapas seguintes.
	

9. Conexão e publicação MQTT
9.1 Configuração do cliente
Conexão MQTT com Last Will
#include <WiFi.h>
#include <PubSubClient.h>
#include "secrets.h"

WiFiClient networkClient;
PubSubClient mqttClient(networkClient);

const char* DEVICE_ID = "aluno01";
const char* TOPIC_AVAILABILITY =
  "ifmg/iot3/turmaA/aluno01/esp32/availability";

unsigned long lastMqttAttempt = 0;
const unsigned long MQTT_RETRY_INTERVAL_MS = 5000;

void connectMqtt() {
  if (WiFi.status() != WL_CONNECTED || mqttClient.connected()) {
    return;
  }

  unsigned long now = millis();
  if (now - lastMqttAttempt < MQTT_RETRY_INTERVAL_MS) {
    return;
  }
  lastMqttAttempt = now;

  Serial.print("Conectando ao broker MQTT...");

  bool connected = mqttClient.connect(
    DEVICE_ID,
    MQTT_USERNAME,
    MQTT_PASSWORD,
    TOPIC_AVAILABILITY,
    1,
    true,
    "offline"
  );

  if (connected) {
    Serial.println(" conectado.");
    mqttClient.publish(TOPIC_AVAILABILITY, "online", true);
  } else {
    Serial.print(" falhou. Estado: ");
    Serial.println(mqttClient.state());
  }
}

void setupMqtt() {
  mqttClient.setServer(MQTT_HOST, MQTT_PORT);
  mqttClient.setBufferSize(512);
}

void maintainMqtt() {
  connectMqtt();
  if (mqttClient.connected()) {
    mqttClient.loop();
  }
}
	





9.2 Publicação periódica de telemetria
Função de publicação
#include <ArduinoJson.h>

const int SENSOR_PIN = 34;
const char* TOPIC_TELEMETRY =
  "ifmg/iot3/turmaA/aluno01/esp32/telemetry";

unsigned long lastTelemetry = 0;
const unsigned long TELEMETRY_INTERVAL_MS = 5000;
unsigned long sequenceNumber = 0;

void publishTelemetry() {
  if (!mqttClient.connected()) {
    return;
  }

  unsigned long now = millis();
  if (now - lastTelemetry < TELEMETRY_INTERVAL_MS) {
    return;
  }
  lastTelemetry = now;

  int sensorValue = analogRead(SENSOR_PIN);

  JsonDocument document;
  document["deviceId"] = DEVICE_ID;
  document["sensor"] = "analogico";
  document["value"] = sensorValue;
  document["unit"] = "raw";
  document["sequence"] = sequenceNumber++;
  document["uptimeMs"] = now;

  char payload[256];
  size_t length = serializeJson(document, payload, sizeof(payload));

  bool published = mqttClient.publish(
    TOPIC_TELEMETRY,
    payload,
    length,
    false
  );

  Serial.print("Telemetria: ");
  Serial.print(payload);
  Serial.println(published ? " [enviada]" : " [falhou]");
}
	









10. Assinatura e controle do atuador
10.1 Callback de mensagens
Recepção e processamento de comando
const int ACTUATOR_PIN = 2;
const char* TOPIC_COMMAND =
  "ifmg/iot3/turmaA/aluno01/esp32/command";
const char* TOPIC_STATE =
  "ifmg/iot3/turmaA/aluno01/esp32/state";

void publishActuatorState(bool state, const char* requestId) {
  JsonDocument response;
  response["deviceId"] = DEVICE_ID;
  response["actuator"] = "led";
  response["state"] = state;
  response["requestId"] = requestId;

  char payload[192];
  serializeJson(response, payload, sizeof(payload));
  mqttClient.publish(TOPIC_STATE, payload, true);
}

void onMqttMessage(char* topic, byte* payload, unsigned int length) {
  Serial.print("Mensagem em ");
  Serial.println(topic);

  JsonDocument command;
  DeserializationError error = deserializeJson(command, payload, length);

  if (error) {
    Serial.print("JSON inválido: ");
    Serial.println(error.c_str());
    return;
  }

  const char* action = command["action"] | "";
  const char* target = command["target"] | "";
  const char* requestId = command["requestId"] | "sem-id";

  if (strcmp(action, "set") != 0 || strcmp(target, "led") != 0) {
    Serial.println("Comando não suportado.");
    return;
  }

  bool newState = command["value"] | false;
  digitalWrite(ACTUATOR_PIN, newState ? HIGH : LOW);
  publishActuatorState(newState, requestId);
}

  bool subscribed = mqttClient.subscribe(TOPIC_COMMAND, 1);

Programa integrado
#include <WiFi.h>
#include <PubSubClient.h>
#include <ArduinoJson.h>
#include "secrets.h"

const int SENSOR_PIN = 34;
const int ACTUATOR_PIN = 2;

const char* DEVICE_ID = "aluno01";
const char* TOPIC_TELEMETRY = "ifmg/iot3/turmaA/aluno01/esp32/telemetry";
const char* TOPIC_COMMAND = "ifmg/iot3/turmaA/aluno01/esp32/command";
const char* TOPIC_STATE = "ifmg/iot3/turmaA/aluno01/esp32/state";
const char* TOPIC_AVAILABILITY = "ifmg/iot3/turmaA/aluno01/esp32/availability";

WiFiClient networkClient;
PubSubClient mqttClient(networkClient);

const unsigned long WIFI_RETRY_MS = 5000;
const unsigned long MQTT_RETRY_MS = 5000;
const unsigned long TELEMETRY_INTERVAL_MS = 5000;

unsigned long lastWifiAttempt = 0;
unsigned long lastMqttAttempt = 0;
unsigned long lastTelemetry = 0;
unsigned long sequenceNumber = 0;

void publishActuatorState(bool state, const char* requestId) {
  JsonDocument response;
  response["deviceId"] = DEVICE_ID;
  response["actuator"] = "led";
  response["state"] = state;
  response["requestId"] = requestId;

  char payload[192];
  size_t length = serializeJson(response, payload, sizeof(payload));
  mqttClient.publish(TOPIC_STATE, payload, length, true);
}

void onMqttMessage(char* topic, byte* payload, unsigned int length) {
  JsonDocument command;
  DeserializationError error = deserializeJson(command, payload, length);

  if (error) {
    Serial.print("JSON inválido: ");
    Serial.println(error.c_str());
    return;
  }

  const char* action = command["action"] | "";
  const char* target = command["target"] | "";
  const char* requestId = command["requestId"] | "sem-id";

  if (strcmp(action, "set") != 0 || strcmp(target, "led") != 0) {
    Serial.println("Comando não suportado.");
    return;
  }

  bool newState = command["value"] | false;
  digitalWrite(ACTUATOR_PIN, newState ? HIGH : LOW);
  publishActuatorState(newState, requestId);
}

void startWifi() {
  WiFi.mode(WIFI_STA);
  WiFi.begin(WIFI_SSID, WIFI_PASSWORD);
  lastWifiAttempt = millis();
  Serial.println("Iniciando conexão Wi-Fi...");
}

void maintainWifi() {
  if (WiFi.status() == WL_CONNECTED) {
    return;
  }

  unsigned long now = millis();
  if (now - lastWifiAttempt >= WIFI_RETRY_MS) {
    Serial.println("Tentando reconectar ao Wi-Fi...");
    WiFi.disconnect();
    WiFi.begin(WIFI_SSID, WIFI_PASSWORD);
    lastWifiAttempt = now;
  }
}

void connectMqtt() {
  if (WiFi.status() != WL_CONNECTED || mqttClient.connected()) {
    return;
  }

  unsigned long now = millis();
  if (now - lastMqttAttempt < MQTT_RETRY_MS) {
    return;
  }
  lastMqttAttempt = now;

  bool connected = mqttClient.connect(
    DEVICE_ID,
    MQTT_USERNAME,
    MQTT_PASSWORD,
    TOPIC_AVAILABILITY,
    1,
    true,
    "offline"
  );

  if (connected) {
    Serial.println("MQTT conectado.");
    mqttClient.publish(TOPIC_AVAILABILITY, "online", true);
    mqttClient.subscribe(TOPIC_COMMAND, 1);
    publishActuatorState(digitalRead(ACTUATOR_PIN) == HIGH, "startup");
  } else {
    Serial.print("Falha MQTT. Código: ");
    Serial.println(mqttClient.state());
  }
}

void publishTelemetry() {
  if (!mqttClient.connected()) {
    return;
  }

  unsigned long now = millis();
  if (now - lastTelemetry < TELEMETRY_INTERVAL_MS) {
    return;
  }
  lastTelemetry = now;

  JsonDocument telemetry;
  telemetry["deviceId"] = DEVICE_ID;
  telemetry["sensor"] = "analogico";
  telemetry["value"] = analogRead(SENSOR_PIN);
  telemetry["unit"] = "raw";
  telemetry["sequence"] = sequenceNumber++;
  telemetry["uptimeMs"] = now;
  telemetry["wifiRssi"] = WiFi.RSSI();

  char payload[256];
  size_t length = serializeJson(telemetry, payload, sizeof(payload));

  bool ok = mqttClient.publish(TOPIC_TELEMETRY, payload, length, false);
  Serial.print(ok ? "Publicado: " : "Falha ao publicar: ");
  Serial.println(payload);
}

void setup() {
  Serial.begin(115200);
  pinMode(ACTUATOR_PIN, OUTPUT);
  digitalWrite(ACTUATOR_PIN, LOW);

  mqttClient.setServer(MQTT_HOST, MQTT_PORT);
  mqttClient.setCallback(onMqttMessage);
  mqttClient.setBufferSize(512);

  startWifi();
}

void loop() {
  maintainWifi();
  connectMqtt();

  if (mqttClient.connected()) {
    mqttClient.loop();
    publishTelemetry();
  }
}

15. Segurança e boas práticas
* Use credenciais individuais ou por grupo quando possível.
* Não reutilize senhas pessoais no broker da disciplina.
* Não publique secrets.h em repositórios públicos.
* Utilize clientId e tópicos exclusivos.
* Valide campos e tipos antes de executar comandos.
* Restrinja o conjunto de ações aceitas pelo dispositivo.
* Evite comandos genéricos que permitam controlar qualquer pino.
* Não exponha broker local diretamente à internet sem configuração segura.
* Prefira TLS quando a infraestrutura fornecida suportar e quando essa exigência não impedir a aprendizagem essencial.
* Registre erros sem imprimir senhas ou tokens.
Escopo da segurança

18. Revisão para a prova teórica
18.1 Síntese conceitual
* A arquitetura IoT separa dispositivo, comunicação, broker/gateway, persistência e interface.
* Wi-Fi fornece conectividade IP; MQTT fornece mensageria sobre essa conectividade.
* O broker desacopla publicadores e assinantes.
* Tópicos organizam fluxos; payloads carregam dados.
* ClientId deve ser exclusivo para evitar encerramento de sessões.
* QoS representa diferentes garantias de entrega.
* Retained fornece o último valor conhecido a novos assinantes.
* Last Will permite indicar desconexão inesperada.
* JSON facilita interoperabilidade, mas deve ser validado.
* Reconexão Wi-Fi e MQTT são problemas distintos.
* O dispositivo deve confirmar o estado do atuador após executar um comando.
